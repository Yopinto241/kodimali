# Typed operating areas and bounded registration loading

The previous web picker required a saved area. Production had only eight active areas, so many wards could not be used to complete registration. The existing `ensure_ward_area(uuid,text)` RPC already permits anonymous applicants to normalize, save and reuse an area beneath an active ward; its execute privilege and deployed definition were verified read-only.

The web registration form now offers **New area name** after choosing a ward. Applicants can either choose an existing area or type one. Submit resolves a typed name through `ensure_ward_area`, verifies the returned parent/type, then sends the saved area ID to signup. Names are normalized and reused case-insensitively under the selected ward by the existing RPC, which locks per ward to prevent duplicate concurrent saves. Saved areas remain available to later applicants even if signup subsequently fails. Supervisor-created agents use the same picker, retain territory boundaries and remain subject to the existing protected creation endpoint. No database migration or new privilege was introduced.

Location lookups now abort after ten seconds, clear loading in `finally`, reject stale results and offer Retry. Area saving has a ten-second deadline and staff creation a twenty-second deadline. Public Auth signup uses a nonpersistent, separate client with a twenty-second fetch abort, so it cannot replace an existing staff/customer session. It does not wait for an additional sign-out request after signup. A timeout is presented as an unconfirmed outcome and asks the user to try signing in before registering again, because a server may have committed the request before the connection ended. English and Swahili messages are included.

Manage mobile source already offers saved areas and a typed new-area field through the same RPC. No native application changes or APK generation are required for the web repair.

Validation: isolated SQL `scripts/test-agent-area-registration.sql` verified anonymous saving into an empty ward, normalized/case-insensitive reuse, valid registration hierarchy and rejection of a district as parent. `scripts/test-agent-registration-web.py` with `TYPED_AREA=1` verified an empty ward, typed-area saving/reuse across applicants, exact signup area ID, a stalled signup that recovers, friendly server/duplicate errors and success at 390px in English/Swahili and 1440px in English. The default mode verified existing saved-area registration. All Auth and area-writing browser requests were intercepted; no test accounts or areas were written in production. All 22 web unit tests, ESLint and the full production build passed. Evidence is in `tmp/typed-area-*.log`.

Released version `a76f0cac-3973-4a0f-a21a-3c43ac3c695c` at 100% web traffic on November 1, 2026. Live intercepted-request checks passed for typed areas and timeout recovery at both phone and desktop widths. The owned preview server and local fixture Postgres were stopped; no APK was created.
